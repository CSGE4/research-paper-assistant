# 科研小助手 Agent

面向科研文献的本地知识库助手：上传 PDF 后自动完成结构化解析与入库，支持**基于原文的问答**（回答带文件名和页码）与**按章节的中文翻译**。

与直接把论文丢给大模型对话不同，本项目的每个结论都能回溯到具体文献的具体页码，用户可以直接翻到原文核对，从而发现模型可能存在的幻觉。

如果想体验上传流程，请传一篇库里没有的 PDF。同一篇重复上传会被 md5 指纹判为「已存在」而跳过，这是幂等设计，不是故障。

## 二、功能

| 功能 | 说明 |
|---|---|
| PDF 上传与解析 | `pymupdf4llm` 转 Markdown，保留标题层级、表格、公式 |
| 结构化抽取 | 标题、作者、摘要、关键词、标题层级、表格、图、公式、参考文献、附录 |
| 语义切块 | 语义切分 + 小块合并 + 递归切分，单块 500~1500 字符 |
| 混合检索 | 向量召回（`text-embedding-v4`）+ BM25 关键词召回，加权融合 |
| 知识问答 | 基于检索到的原文作答，输出末尾标注文件名与页码 |
| 中文翻译 | 按论文章节翻译，中英对照，表格与公式原样保留 |
| 联网搜索（可选） | 问答页侧边栏有开关，**默认关闭**。打开后先查本地库，本地查不到才联网，回答里标注「来自互联网」并给出来源链接 |

## 三、技术架构

```
                            ┌──────────────── 入库 ────────────────┐
 PDF ──pymupdf4llm──> Markdown ──语义切分──> 块 ──合并/递归切分──> 约 120 块/篇
                                                          │
                                        ┌─────────────────┴─────────────────┐
                                        ▼                                   ▼
                              text-embedding-v4                     jieba 分词
                                        │                                   │
                                   Chroma 向量库                      bm25.pkl
                                        │                                   │
 用户提问 ──────────────────────> 向量召回 Top-10              BM25 召回 Top-10
                                        └─────────────────┬─────────────────┘
                                                          ▼
                                   加权融合：score = α·BM25 + (1-α)·向量
                                                          ▼
                                    Top-10 原文 → LLM → 答案 + 来源页码
```

关键设计：

- **两库分离**：向量库存块用于检索，`chroma_structured.json` 存整篇结构化信息用于展示与翻译，互不干扰。
- **入库时抽取**：结构化字段在入库时用完整按页原文抽取，不从切块反推，避免跨页信息丢失。
- **重复上传幂等**：`md5.txt` 记文件指纹、`embedding.json` 记页级向量，同一篇论文重复上传直接跳过，不会重复入库。
- **α 取 0.35**：向量权重更高。比赛论文均为英文，中文提问走跨语言匹配，向量贡献大于关键词；α 从 0.20 到 0.80 做过扫描，0.35 在概念查询与精确查询之间取得最佳平衡。

## 四、目录结构

| 文件 | 职责 |
|---|---|
| `web.py` | Streamlit 入口页：PDF 上传、入库进度、文档结构化展示 |
| `pages/app.py` | 文献问答页（Streamlit 多页应用）：提问、答案与来源页码、按节翻译 |
| `knolege.py` | 入库：PDF → Markdown → 切块 → 嵌入 → Chroma，并构建 BM25 索引 |
| `paper_extractor.py` | 结构化抽取：标题/作者/摘要/标题层级/表格/图/公式/参考文献/附录 |
| `model_extractor.py` | 规则抽取失败时调用大模型兜底，结果做原文子串校验防幻觉 |
| `vctor.py` | 检索层：向量与 BM25 双路召回 |
| `bm25_score.py` | 双路结果归一化与加权融合 |
| `rag.py` | 问答链：检索 → 拼接上下文 → LLM 作答 → 标注来源 |
| `agent.py` | Agent 组装：工具注册与系统提示词 |
| `tool_1.py` | 翻译工具（按章节翻译，带缓存） |
| `tool_2.py` | 联网搜索工具（Tavily），由问答页开关控制，缺 key 时自动退回纯本地检索 |
| `tool_3.py` | 本地知识库检索工具 |
| `graph tree.py` | 对外服务门面，统一暴露文档信息接口 |
| `config.py` | 全局配置：路径、切块参数、集合名 |

## 五、安装与运行

### 1. 环境要求

- Python **3.13**（3.10 及以上需自行验证）
- Windows / Linux 均可
- 需要能访问 DashScope 接口的网络

### 2. 安装依赖

```bash
pip install -r requirements.txt
```

### 3. 配置环境变量

```bash
# Windows
copy .env.example .env

# Linux / macOS
cp .env.example .env
```

然后编辑 `.env`，**至少填入 `DASHSCOPE_API_KEY`**。完整变量说明见第六节。

> `.env` 已被 `.gitignore` 忽略，不会进入仓库。仓库里只有不含真实密钥的 `.env.example`。

### 4. 启动

```bash
streamlit run web.py
```

浏览器打开 `http://localhost:8501`。

### 5. 首次使用

仓库已自带 6 篇论文的入库数据，启动后问答页就有内容，可以直接提问，例如「Transformer 的 BLEU 分数」「LoRA 的秩 r 一般取多少」。

想完整走一遍入库流程：

1. 上传一篇库里没有的 PDF
2. 等待入库完成（依次执行解析、切块、嵌入、结构化抽取，单篇约 30~90 秒）
3. 回到问答页提问

> 同一篇重复上传不会重复入库，`md5.txt` 里记着已入库文件的指纹，会直接提示「已存在」。

入库产物一共五项：

| 产物 | 内容 |
|---|---|
| `chroma/` | 向量库，检索用 |
| `chroma_structured.json` | 整篇结构化信息，展示与翻译用 |
| `embedding.json` | 页级向量，重复上传查重用 |
| `bm25.pkl` | 分词后的关键词索引 |
| `md5.txt` | 已入库文件的指纹 |

这五项已随仓库提供样例数据（见第一节）；自己重新入库会覆盖它们。

## 七、常见问题

**Q：启动后问答一直说查不到？**
先确认问的论文在库里，「文档」页能看到 6 篇样例。如果删过入库产物，需要重新上传 PDF 完成入库。

**Q：能开多个进程提高并发吗？**
不能。BM25 索引 `bm25.pkl` 是进程内维护、整份覆盖写的，多进程会互相覆盖并导致 BM25 与向量库不一致。**必须单进程运行。**

**Q：报 429 或调用超时？**
DashScope 免费额度有并发限制，降低并发、稍等重试即可。

**Q：`chroma.sqlite3` 报 `readonly database`？**
说明同时有另一个进程持有该库（例如 Streamlit 未关闭又启动了一次），关掉多余进程再试。

**Q：为什么问答页回答的页码偶尔不准？**
页码来自检索命中的块元数据，模型只负责复述。若发现页码与原文不符，属于模型复述错误，可直接翻原文核对——这正是设计上要求标注来源的目的。
